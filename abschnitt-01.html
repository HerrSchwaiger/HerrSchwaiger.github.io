Information

Ein Computer versteht nur eine einzige Sprache: Folgen von Nullen und Einsen, den Maschinencode. Kein Mensch schreibt Programme direkt in dieser Form -- stattdessen schreibt ihr Quellcode in einer Programmiersprache wie Java, die für Menschen lesbar ist. Damit der Computer diesen Code trotzdem ausführen kann, muss er zuerst übersetzt werden. Wie diese Übersetzung funktioniert, ist das Thema dieses Abschnitts. Fülle das Arbeitsblatt anhand des Informationstextes aus.

Compiler vs. Interpreter

Es gibt zwei grundsätzliche Wege, wie Quellcode zu einem lauffähigen Programm wird:

Compiler

Ein Compiler übersetzt den gesamten Quellcode auf einmal in Maschinencode. Erst danach kann das fertige Programm gestartet werden. Das Übersetzen heißt kompilieren.

Interpreter

Ein Interpreter liest den Quellcode Zeile für Zeile und führt jede Zeile sofort aus, ohne vorher das gesamte Programm zu übersetzen.

Kompilierte Programme starten in der Regel schneller, weil die Übersetzung schon vorher passiert ist. Interpretierte Programme lassen sich dagegen leichter testen, weil man einzelne Zeilen sofort ausprobieren kann, ohne das ganze Programm neu zu übersetzen. C wird klassischerweise kompiliert, Python klassischerweise interpretiert.

Maschinencode und Bytecode -- der Sonderfall Java

Maschinencode besteht aus Befehlen, die exakt auf einen bestimmten Prozessortyp zugeschnitten sind. Ein für einen Intel-Prozessor kompiliertes Programm läuft deshalb nicht automatisch auf jedem anderen Prozessor. Java geht einen anderen Weg und fügt eine Zwischenstufe ein, den Bytecode.

Der Bytecode ist auf keinen bestimmten Prozessor zugeschnitten. Er läuft auf jedem Gerät, für das es eine JVM gibt -- der Bytecode selbst muss dafür nicht neu übersetzt werden. Die JVM übernimmt zur Laufzeit die Übersetzung in den Maschinencode des jeweiligen Geräts, teils zeilenweise interpretiert, teils direkt in schnellen Maschinencode übersetzt. Java nutzt also beide Prinzipien: einen Compiler von Quellcode zu Bytecode, und die JVM, die diesen Bytecode ausführt.

Vergleich von Programmiersprachen

Nicht jede Sprache setzt auf dasselbe Prinzip. Die folgende Tabelle vergleicht vier bekannte Sprachen:

Sprache Übersetzungsart Typische Einsatzgebiete
Java Compiler zu Bytecode, dann JVM Unternehmensanwendungen, Android-Apps, Backend-Systeme
Python Interpreter Datenanalyse, Skripte, Prototypen, KI
C Compiler zu Maschinencode Betriebssysteme, eingebettete Systeme, Treiber
JavaScript Interpreter / JIT im Browser Interaktive Webseiten

Recherchiert, was ein JIT-Compiler (Just-in-Time-Compiler) innerhalb der JVM genau macht und warum er ein Kompromiss zwischen den Vorteilen von Compiler und Interpreter ist.

Überlegt zunächst, welchen Nachteil reines Interpretieren gegenüber kompiliertem Code hat.

JIT steht für "just in time" -- der Compiler übersetzt also nicht vorher alles, sondern erst dann, wenn ein Teil des Bytecodes wirklich gebraucht wird, und merkt sich häufig genutzte Teile.
